# Remaining_Survivor

Unity **2022.3.45f1**, Built-in Render Pipeline (no URP/HDRP), legacy Input Manager (`UnityEngine.Input`, not the new Input System package — none installed). 2D side-scrolling platformer. Unity MCP is set up for this project; prefer it (or a checked-in `Assets/Scripts/Editor/*.cs` `[MenuItem]` tool) over hand-editing scene/prefab/animator YAML.

## Scene: `Assets/Scenes/SampleScene.unity`

- **Grid/Ground** — the level: a hand-designed `Tilemap` (+`TilemapRenderer`+`TilemapCollider2D` `usedByComposite`+`CompositeCollider2D` Outlines+static `Rigidbody2D`), layer `Ground`. Grid at world origin, cell = 1 unit (cell `(x,y)` spans world `x..x+1`, `y..y+1`); spans world x -11..23, y -17..+1, main floor top at y -10. Tiles are Cainos `TP Ground` tile assets with per-cell `Tile.ColliderType.Grid` forced (source tiles default to `Sprite` collider, which traces bumpy silhouettes instead of a flat top). Edit it by painting on `Grid/Ground` with the Tile Palette, or by dragging `TX Tileset Ground` sprites into the scene root and running `Tools/Remaining Survivor/Bake Ground Sprites` (`Editor/GroundBaker.cs`: snaps each loose sprite into its cell, keeps 90° rotations/flips, warns and skips on an occupied cell, deletes the sprite; additive). Tiles are **solid from every side** for the Knight (see `KnightMove`), so every part of the layout must be reachable with a 2.3 jump, and passages need ≥1 cell of headroom. For climbs that feel easy (not just technically possible): each step rises ≤2 and is **adjacent** to the previous one (its side is a solid wall from the lower top up to its own top, so "hold direction + jump" works), and every surface you jump from has **≥4 cells of clear space above it** (a tile hanging lower than that clips the jump — the old single-tile zig-zag stones on the right failed both rules). The right side is built this way: a stepped cliff x17..22 (tops -15, -13, -11, -9, -7, -7) from the bottom floor, then a bridge x16..19 (top -6) back to the ledge.
- **Knight** — the player. `SkeletonAnimation`+`KnightControl` (Spine; animation name → `SetAnimation` mapper) + `KnightMove` (movement/state machine, no physics — see Scripts) + `CapsuleCollider2D` (trigger, detection-only) + `PlayerHealth` + `PlayerCombat`. Tag `Player`, layer `Player`. `minX`/`maxX` -10.5/22.5, `respawnBelowY` -19 (keep below the lowest tile).
- **Main Camera** — orthographic size 6, `CameraFollow` (follows Knight on X and Y with `yOffset` 1, **no bounds** — the user wants the camera never limited, so don't reintroduce clamping to level edges).
- **Enemies** — container with 4 instances of `Assets/Prefabs/SkeletonEnemy.prefab` (a variant of BluBlu's `skeleton rotten.prefab`, scaled to `0.08` — the raw rig is ~13.5 units tall at scale 1), layer `Enemy`.
- **Canvas** — `HealthBarSlider` (a uGUI `Slider`, top-left anchored, red fill, non-interactable) + `PlayerHealthBarUI`, wired to Knight's `PlayerHealth`.

## Scripts (`Assets/Scripts/`)

- `KnightMove.cs` — player state machine (`Free/Action/Air/Dead`). Movement is raycast-only against `groundLayer`: X (walk + knockback) stops at walls (`MoveXUntilWall`, 3 horizontal rays up the body), rising stops at ceilings (`TryGetCeiling`), falling lands on the first surface swept past (`TryGetGround`). All three are needed: the composite collider is outlines-only, so if the body ever gets *inside* solid tiles the down-ray hits the tile's inside bottom edge and the Knight "stands" buried in the floor. `bodyHeight` (0.8) must stay < 1 so it fits 1-cell gaps in the layout. Public hooks added for combat: `TakeHit(knockbackDir, knockbackDistance)`, `Die()`, `IsDead`, `event OnAttackStarted` (fires at the start of the J/K attack animations). Don't duplicate its private key handling — hook these instead. `HandleActions()` (and therefore attacking) only runs in `State.Free`; `TakeHit()` unconditionally overwrites whatever animation is currently playing, so nothing may call it faster than `PlayerHealth.invulnerabilityDuration` allows (see below) or the player gets stun-locked, unable to ever attack again.
- `CameraFollow.cs` — attached to Main Camera; smooth, unbounded X+Y follow of `target` (+`yOffset`).
- `PlayerHealth.cs` / `PlayerCombat.cs` — player HP + attack hit detection (`OverlapCircle` on `OnAttackStarted`, no trigger colliders/Rigidbody2D involved). `invulnerabilityDuration` (1.0s) must stay comfortably longer than the "Get Hit" animation and than how often a swarm of enemies can realistically land hits — this is what prevents the stun-lock above (a swarm re-triggering `TakeHit()` before the current hit reaction finishes, permanently stuck in `State.Action`). Both `TakeDamage`/enemy `TakeDamage` take the attacker's position and apply a small instant knockback + a brief red tint flash (`Skeleton.R/G/B` for the player, cached `SpriteRenderer` colors for enemies) so hits read as impactful.
- `EnemyHealth.cs` / `EnemySkeleton.cs` — enemy HP (30, dies in 2 player hits) + AI (`OverlapCircle` detection, raycast-to-ground movement mirroring `KnightMove`'s approach, masked to `Ground`). Tuned down from initial values (`attackDamage` 6, `attackCooldown` 1.8s, `detectionRadius` 3.5) after early playtesting found the enemies too aggressive/swarmy.
- `PlayerHealthBarUI.cs` — thin wrapper around a `Slider`.
- `Editor/GroundBaker.cs` — see Scene section above.

## Layers & tags

`Player` (8), `Enemy` (9), `Ground` (10) — all `LayerMask` fields on the above scripts must reference these. **Unity-MCP gotcha**: set a `LayerMask` property via `manage_components` with `{"value": <bitmask>}`, not `{"m_Bits": ...}` — the latter silently no-ops (leaves the field at 0/nothing) without erroring, which previously caused ground collision and enemy/player detection to silently fail. Always read the property back after setting a `LayerMask` to confirm.

**More Unity-MCP/testing gotchas learned the hard way:**
- Editing a public field's *default value* in a `.cs` file does **not** retroactively update that field on already-serialized component instances/prefabs (Unity keeps the old serialized value). After changing a default that an existing instance should pick up, explicitly push it with `manage_components set_property` and read it back to confirm — don't assume the source edit was enough.
- `PlayerSettings.runInBackground` is **off** in this project. Without it, Unity freezes the entire Play-mode frame loop (including coroutines/animations) whenever the Editor window lacks OS focus, which makes automated testing through Unity-MCP look like a stuck game (`Time.time` never advancing). After entering Play mode, run `Application.runInBackground = true;` via `execute_code` (session-only, not saved).
- Check `mcpforunity://editor/state` (`play_mode.is_playing`) before editing the scene: the user may have left Play mode running, and every scene edit made during Play (by MCP or by hand — e.g. dragging in sprites) is discarded when Play stops. `GroundBaker` refuses to run in Play mode for this reason.
- After layout changes, check that the whole level is still reachable: many surfaces can only be reached by a roundabout route (currently the upper ledges and upper-left section are reached from the bottom-right floor via the right-side stepping stones, not from the main floor). Best done as a search from spawn over simulated walks/jumps (both directions, walk/run speed, mid-air direction reversal), marking which tile tops get stood on. Traversal can be checked without keyboard input by calling `KnightMove`'s private `MoveXUntilWall`/`TryGetGround`/`TryGetCeiling` via reflection from `execute_code` in a simulated walk/jump loop (edit mode is fine; call `TilemapCollider2D.ProcessTilemapChanges()` + `CompositeCollider2D.GenerateGeometry()` first if tiles were just edited in the same call).

## Animator: `skeleton rooten.controller`

Shipped as a zero-parameter "cycle through every animation once" demo. Reworked for gameplay: added `IsWalking` (bool), `Attack`/`Hit`/`Dead` (triggers); `Idle↔Walk` gated on `IsWalking`; `Walk→Attack` gated on trigger; removed the stock auto-transitions `Attack→Get Hit`, `Get Hit 2→Death Skeleton rotten`, and `Death Skeleton rotten→Dance` (all three demo-only trip hazards — the first two would misfire gameplay attack/damage timing, the last would make corpses stand up); added `Any State→Get Hit`/`Any State→Death Skeleton rotten` on the `Hit`/`Dead` triggers instead.
